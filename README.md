# Machine Failure Prediction Using Traditional Machine Learning Algorithms

## 1. Project Overview

Machine failures can cause unexpected production interruptions, increase maintenance costs, and reduce productivity in industrial environments.

This project aims to develop a Machine Learning classification system that predicts whether a machine will experience a failure based on its operating conditions and sensor measurements.

Using the AI4I 2020 Predictive Maintenance Dataset, we explore different traditional Machine Learning algorithms and evaluate their ability to identify potential machine failures.

This is a **Binary Classification** problem:

- **0 – No Failure:** The machine operates normally.
- **1 – Failure:** The machine experiences a failure.

## 2. Project Objectives

- Analyze machine operating conditions and sensor measurements.
- Perform data cleaning and Exploratory Data Analysis (EDA).
- Identify patterns and relationships between sensor features and machine failures.
- Engineer new features based on physical and mechanical relationships.
- Handle class imbalance using SMOTE.
- Train and compare different traditional Machine Learning algorithms.
- Optimize the best-performing model using hyperparameter tuning.
- Evaluate model performance using classification metrics.

## 3. Dataset Description

**Dataset:** AI4I 2020 Predictive Maintenance Dataset

**Source:** [UCI Machine Learning Repository – AI4I 2020 Predictive Maintenance Dataset](https://archive.ics.uci.edu/dataset/601/ai4i+2020+predictive+maintenance+dataset)

The dataset contains 10,000 records representing machine operating conditions and failure information.

### Main Features

| Feature | Description |
|---|---|
| Type | Product quality type (L, M, H) |
| Air temperature [K] | Surrounding air temperature |
| Process temperature [K] | Machine process temperature |
| Rotational speed [rpm] | Machine rotation speed |
| Torque [Nm] | Rotational force |
| Tool wear [min] | Tool usage time |
| Machine failure | Target variable (0 or 1) |

**Target Variable:** `Machine failure`

The dataset also includes failure-specific columns and identification fields. These are removed during preprocessing to avoid target leakage and unnecessary identifiers.

## 5. Project Workflow

### Step 1: Data Loading and Understanding
- Extract and load the dataset.
- Inspect dataset dimensions and records.
- Understand feature descriptions and data types.

### Step 2: Data Cleaning and Preprocessing
- Remove unnecessary identifier columns.
- Drop target leakage features.
- Check missing values and duplicate records.
- Validate physical and logical data consistency.

### Step 3: Exploratory Data Analysis (EDA)
- Analyze target class distribution.
- Explore categorical and numerical features.
- Visualize sensor distributions using histograms.
- Detect potential outliers using boxplots and the IQR method.
- Analyze correlations using heatmaps.
- Compare sensor measurements between normal and failed machines.

### Step 4: Feature Engineering
Create four additional features to help the models understand machine operating conditions:

1. `Temp_Difference` – Difference between process temperature and air temperature.
2. `Power_kW` – Estimated mechanical power generated by the machine.
3. `Overstrain_Index` – Combined tool wear and torque indicator.
4. `Thermal_Stress_Index` – Combined temperature difference and tool wear indicator.

### Step 5: Feature Selection and Data Preparation
- Select relevant features.
- Split data into 80% training and 20% testing sets.
- Apply One-Hot Encoding to categorical features.
- Apply StandardScaler for feature scaling.
- Use SMOTE on the training data to handle class imbalance.

### Step 6: Model Training and Comparison

Train and evaluate five traditional Machine Learning algorithms:

1. Logistic Regression
2. Decision Tree
3. Random Forest
4. K-Nearest Neighbors (KNN)
5. XGBoost

### Step 7: Model Evaluation

Evaluate model performance using:

- Accuracy
- Precision
- Recall
- F1-Score
- ROC-AUC
- PR-AUC
- Confusion Matrix

### Step 8: Hyperparameter Tuning

Apply GridSearchCV with cross-validation to optimize the XGBoost model and improve its predictive performance.

### Step 9: Decision Threshold Optimization

Experiment with different classification thresholds and select 0.85 as the chosen threshold to improve precision while maintaining useful recall.

### Step 10: Final Model Comparison

Compare all five models using the optimized decision threshold and select the best-performing model.

## 6. Final Model Performance

After model comparison and optimization, Tuned XGBoost achieved the best overall balance between identifying machine failures and reducing false alarms.

### Final Results (Threshold = 0.85)

| Model | Accuracy | Precision | Recall | F1-Score | PR-AUC |
|---|---:|---:|---:|---:|---:|
| **Tuned XGBoost** | **99.00%** | **90.00%** | **79.41%** | **84.38%** | **0.8798** |
| Random Forest | 98.75% | 93.88% | 67.65% | 78.63% | 0.8585 |
| Decision Tree | 96.75% | 51.40% | 80.88% | 62.86% | 0.4223 |
| KNN | 95.85% | 42.11% | 70.59% | 52.75% | 0.4570 |
| Logistic Regression | 96.00% | 43.88% | 63.24% | 51.81% | 0.4684 |

**Selected Model: Tuned XGBoost**

At the selected threshold of 0.85, the model achieved:

- 99.00% Accuracy
- 90.00% Precision
- 79.41% Recall
- 84.38% F1-Score
- 0.8798 PR-AUC

These results indicate that the model can identify a substantial proportion of machine failures while reducing false alarms.

## 7. Conclusion

This project demonstrates how traditional Machine Learning algorithms can be applied to predictive maintenance problems.

After performing data preprocessing, exploratory analysis, feature engineering, model comparison, and hyperparameter tuning, XGBoost was selected as the best overall model.

The final model achieved an accuracy of 99.00%, precision of 90.00%, and recall of 79.41% at the optimized decision threshold.

The results demonstrate the potential of Machine Learning for supporting machine condition monitoring and maintenance planning.

**Note:** This project is an academic experiment using the AI4I 2020 dataset. Further validation using real industrial machine data is necessary before practical deployment.
